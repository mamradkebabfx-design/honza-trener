## Project

Landing page for **Honza Procházka**, a personal fitness trainer in Prague specializing in kinesiology. Vanilla HTML / CSS / JS — no build step, no framework, no package manager. The only backend code is a single Vercel serverless function (`api/contact.js`) that handles form submissions. Primary goal is client acquisition (booking first session). Language is Czech.

The business brief (tone, target audience, services, pricing, page structure) lives in `honza-trener.md`. When writing copy or changing structure, read that file first — it defines the tone of voice (calm, human, non-aggressive, low-pressure CTA) and explicitly lists things to avoid (overhyped fitness claims, generic marketing phrases).

## Running locally

Serving the static files is enough for everything except the contact form:

```
python3 -m http.server 8000
# then open http://localhost:8000
```

`file://` breaks relative paths and `localStorage`, so always serve over HTTP. **The contact form (`/api/contact`) won't work under `python3 -m http.server`** — that endpoint only exists when the Vercel runtime is serving the repo. For local end-to-end form testing, use `npx vercel dev` (no install needed), which boots a local replica of the Vercel edge + serverless functions and loads env vars from a local `.env` file if present. Without `vercel dev`, test the form on the deployed Vercel URL.

**`script.js` caching gotcha with `python3 -m http.server`:** Python's SimpleHTTPServer sends `Last-Modified` but no `Cache-Control`, so Chrome's disk cache can keep serving a stale `script.js` even after a normal reload or after navigating with a cache-busting query string on the *page* URL — the `<script src="script.js">` sub-resource request itself is unaffected by that. Symptom: edited JS silently doesn't run, with zero console errors, and `typeof someNewFunction` returns `"undefined"` even though `fetch('/script.js', {cache:'no-store'})` shows the new code is being served. **Fix: hard reload (Cmd+Shift+R), not a normal refresh**, whenever testing a `script.js` change locally. This is a local-dev-only issue — Vercel/CDN cache invalidates correctly per deploy, so it doesn't affect production.

## Architecture

Five files make up the whole app:

Current section order: hero (`#top`) → offer/value-stack for the free consultation (`.offer`, `#konzultace`, heading "Jak probíhá konzultace zdarma?") → problem/for-whom (`.forwhom`, no id) → about/proof (`#o-mne`) → benefits (`#benefity`, 4 cards) → how-it-works steps (`.steps`, `#jak-to-funguje`) → CTA/contact (`#kontakt`) → footer. (The offer section used to sit after for-whom; moved directly under the hero at the user's request on 2026-08-28 so the "what the free consultation looks like" pitch reads immediately. The FAQ section that used to sit between steps and CTA was removed on 2026-08-28 — no FAQPage JSON-LD anymore either.) The primary (and currently only) CTA throughout is a **free intro consultation** ("Zarezervovat konzultaci zdarma") — there is no pricing section on the live page (see Conventions section below for why, and the git tag that preserves the version with pricing). Contains inline JSON-LD structured data (LocalBusiness, Person, Service+Offer with just a 0 Kč "Úvodní konzultace" offer) — keep it in sync with visible copy when editing pricing or contact info. Footer links to `privacy-policy.html`.
- `privacy-policy.html` — GDPR-compliant privacy policy page in Czech. Covers data collection from contact form, legal basis, security measures, retention period, user rights, and contact info. Required for Meta Ads compliance.
- `styles.css` — all styles. Design tokens are CSS custom properties on `:root` (colors, radius, shadow, easing). Minimalistic aesthetic: black/white/gray with a single green accent (`--accent: #14a277`). Mobile-first, single stylesheet, no preprocessor.
- `script.js` — sticky nav shadow, mobile menu toggle, IntersectionObserver reveal animations (`.reveal` → `.visible`), booking modal open/close logic (see below), contact form AJAX submission to `/api/contact` (JSON body) with loading/success/error states.
- `api/contact.js` — Vercel serverless function (Node.js runtime, ES module). Parses JSON body, checks the honeypot, server-side validates `name` / `email` / length limits, then calls the Resend API (`https://api.resend.com/emails`) using `RESEND_API_KEY` from env. Sends plain-text mail to `honza.sac@gmail.com` from `onboarding@resend.dev` with `reply_to` set to the visitor's email. Uses native `fetch` — no npm dependencies, so there is still no `package.json`.

## Contact form

The form posts JSON to `/api/contact` (same-origin Vercel function) which relays the message to `honza.sac@gmail.com` via Resend. Fields: `name` (required), `email` (required, regex-validated), `phone` (optional), `message` (optional), `botcheck` (honeypot hidden checkbox — non-empty value silently succeeds without sending). The destination address is hardcoded in `api/contact.js`; change it there if needed.

- **Why same-origin** — this replaced the original Web3Forms integration because **O2 Czech Republic intercepts TLS for `api.web3forms.com`** and serves a `*.o2.cz` cert instead of the real one, causing "Failed to fetch" / Safari "Load failed" for any O2 customer, *including* O2 mobile data (O2 is both an ISP and a mobile carrier in CZ). Hosting the endpoint under `honza-trener.vercel.app/api/contact` — the same origin as the site itself — makes it uninterceptable. **Before reintroducing any third-party form service, verify with `curl -v https://<service-domain>/` that the cert subject/issuer match the expected service and are NOT `*.o2.cz`.**
- **Resend sender** — currently still using Resend's shared `onboarding@resend.dev`. Works, but limited deliverability and unbranded. **Next step (pending — domain `honzacoach.cz` is attached but Resend not yet verified):** in Resend dashboard → Domains → Add Domain → `honzacoach.cz` → add the shown SPF TXT + DKIM CNAME records into Forpsi DNS editor (see Deployment → Forpsi section below for path) → wait for "Verified" → then change `from` in `api/contact.js` from `'onboarding@resend.dev'` to `'Honza Procházka <noreply@honzacoach.cz>'`. Single-line change + commit + push.
- **Env var** — `RESEND_API_KEY` must be set in Vercel dashboard (Project → Settings → Environment Variables, all three environments). Never commit the key to git. If the var is missing, `api/contact.js` returns 500 with "Server není nakonfigurovaný."
- **Secrets hygiene** — `.gitignore` blocks `.env*`, `*.key`, `*.pem`, `re_*`, `sk_*`, `pk_live_*`. If you add a new secret type with a different prefix, extend the patterns. Past incident (2026-05-06): a Resend API key was committed as a standalone file → rotated in Resend, history rewritten with `git filter-repo`, force-pushed. **Never paste a key into a file, even temporarily — Vercel env vars only.**
- **Resend account email = API key scope** — Resend API keys are scoped to a workspace. Changing the Resend account email (2026-05-21) created a new workspace and silently invalidated the old API key in Vercel — the form returned 502 with no logs in Resend. Fix: create a new API key in the new workspace → update `RESEND_API_KEY` in Vercel → redeploy. The `onboarding@resend.dev` sender can also only deliver to the email registered with the active Resend workspace — keep recipient email and Resend account email in sync until a custom sender domain is verified.
- **`form.name` trap** — still worth knowing if anyone refactors: accessing form fields via `form.fieldName` does NOT work for a field called `name`, because `HTMLFormElement.name` reflects the form element's own `name` attribute (a string). Current code uses `FormData` — keep it that way, don't "simplify" to `form.name.value`.

## Booking modal (Google Calendar Appointment Schedules)

All "book free consultation" CTAs (`.js-book-trigger` class — hero primary button, nav "Zdarma konzultace", offer/about section buttons, sticky mobile CTA; 5 elements total as of 2026-08-28) open a modal (`#bookingModal` in `index.html`, styled in `styles.css` under `/* ---------- BOOKING MODAL ---------- */`) instead of scrolling to `#kontakt`. The modal embeds a **Google Calendar Appointment Schedule** via iframe (`#bookingIframe`, lazy-loaded — `src` is only set from `data-src` on first open, in `script.js`).

- **Why Google Calendar instead of Cal.com/Calendly:** the user already has a Google account, so this needed no new third-party signup — appointment scheduling is free on personal Google accounts (not just Workspace) and integrates natively with the Google Calendar the user already checks.
- **Booking flow:** client picks a date/time slot, then fills one combined form (first name, last name, email, phone — phone added as a custom "Phone number" field type in the schedule's booking-form settings). This is Google's standard one-screen form; there's no progressive one-field-at-a-time reveal — that would require a fully custom form + Calendar API integration, decided against as unnecessary complexity for the win.
- **Where the schedule lives:** Google Calendar → the appointment schedule is named "Úvodní konzultace zdarma" (currently 15 min, being changed to 30 min — see below for why no code change is needed for that).
- **Updating the schedule (duration, availability, questions):** edit it directly in Google Calendar — the iframe `src` embeds the schedule by its fixed ID (the long token in the URL, e.g. `AcZssZ...`), so changing duration, weekly availability, or booking-form fields on the *same* schedule needs **no code change** and no new embed code. A new embed code is only needed if a **new/different** schedule is created (different ID).
- **Working days / weekly availability location in Google Calendar's schedule editor:** "Scheduling window" (visible first) only controls *how far ahead* bookings are allowed (max days in advance, min notice hours) — NOT which days of the week are open. The actual day-of-week toggles live further down in a separate "General availability"/"Availability" section (below Scheduling window, above "Adjusted availability" which is for one-off date exceptions like holidays).
- **Getting the embed code:** Google Calendar → the schedule's row in the left sidebar → hover → three-dot menu (⋮) → **Sharing options** → **Website embed** → **Inline booking page** → **Copy code**. The plain "Copy link"/"Preview" popup (opened from clicking the event/schedule directly) does NOT give the embed code — that's a separate, easy-to-miss menu path.
- **CSS gotcha fixed once already:** `.booking-modal__box` needs an explicit `height` (not just `max-height`) for its `flex:1` child (`.booking-modal__body`, holding the iframe) to actually fill the box — `max-height` alone lets the flex column shrink to content and the iframe renders at 0 height.
- **The Google widget's day-column count is responsive to iframe width** (not a Google setting) — it shows more days side by side the wider the iframe is. `.booking-modal__box`'s `max-width` (currently `980px`, up from an initial `720px`) controls this: `720px` showed 2 days, `980px` shows ~3–4 days, `1400px` shows a full week. Since the box is `width:100%` with that `max-width` as a ceiling, it's safe to raise further — it still shrinks correctly on smaller viewports.
